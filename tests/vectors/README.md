# Conformance vectors

## Vendored upstream fixtures

These files are vendored, unmodified copies of the official pikaid
interoperability fixtures published by the reference PHP implementation:

- Source: <https://github.com/pikaid/pikaid-php/tree/v1.2.0/tests/vectors>
- Tag: `v1.2.0`
- Commit: `e3f843edeb5157a5d2d25196cac0d69580810a95`
- Retrieved: 2026-11-06

| File | Upstream path | SHA-256 |
| ---- | ------------- | ------- |
| `pikaid-v1.json` | `tests/vectors/pikaid-v1.json` | `b0c9dfdd063613424414fef5c9065fbd2f81d645d0ab42b34e27cde715613500` |
| `pikaid-v1.schema.json` | `tests/vectors/pikaid-v1.schema.json` | `4441d4dbaa6c5450ae9cbfb2438c53bc0421bba2b7fcc9ef9b158e5d1de0759e` |

The historical `pikaid-v1` filename does **not** imply a versioned identifier
format. The pikaid identifier format is immutable and unversioned; the fixtures
target specification revision 1.0.4.

The fixtures are independent interoperability data, not the normative
definition. In any conflict, the canonical specification wins:

- <https://github.com/pikaid/pikaid-specs/blob/v1.0.4/README.md>
- Pinned commit: `17014d76f568c3ac9f9ce2927c1a018fdbc36d1d`

The vectors were downloaded from the pinned commit, not from a mutable branch.
`tests/conformance.rs` checks their declared metadata against the crate
constants and exercises every valid and invalid entry.

## Independently generated oracle table

`oracle-cases.json` is **not** vendored from another implementation. It is
generated by `scripts/generate_oracle_cases.py`, a standalone Python program
that recomputes the 1.0.4 arithmetic from first principles and never imports,
links or executes this crate. It is therefore a second, independent oracle
alongside the pikaid-php fixtures.

| Property | Value |
| -------- | ----- |
| Generator | `scripts/generate_oracle_cases.py` (Python 3.9+, standard library only) |
| Spec revision | `1.0.4` |
| Spec commit | `17014d76f568c3ac9f9ce2927c1a018fdbc36d1d` |
| Reference fixture commit | `e3f843edeb5157a5d2d25196cac0d69580810a95` |
| SHA-256 | `4acbeded373feb765572b5f5e6e4ff0238ff82eaaee5ad2fc9d1bddafd4021de` |
| Valid cases | 334 |
| Invalid text cases | 22 |
| Invalid binary cases | 8 |

`tests/oracle.rs` pins the SHA-256 above, so the table cannot be edited without
regenerating it. CI runs `python3 scripts/generate_oracle_cases.py --check`,
which fails if the committed table is stale, and then runs the oracle test
suite. To regenerate after an intentional corpus change:

```sh
python3 scripts/generate_oracle_cases.py
python3 scripts/generate_oracle_cases.py --check
```

Then update the `ORACLE_SHA256` constant in `tests/oracle.rs` and the digest in
`.github/workflows/ci.yml`. The table must keep LF line endings; `.gitattributes`
marks `tests/vectors/**` as `-text` so checkouts on Windows cannot rewrite it.
